# Alembic Migration Guidelines

## Naming Convention

All migration files in this project follow a **sequential numbering format** for consistency and readability.

### Format

```
{sequence_number}_{descriptive_name}.py
```

### Examples

- `001_initial.py` - Initial database setup
- `002_add_session_profiles.py` - Add session profiles table
- `003_add_skills_table.py` - Add skills taxonomy table

### Rules

1. **Sequential Numbers**: Use 3-digit zero-padded numbers (001, 002, 003, etc.)
2. **Descriptive Names**: Use snake_case for descriptive operation names
3. **No Timestamps**: Do not include dates or timestamps in filenames
4. **No Hash IDs**: Do not use Alembic-generated hash IDs

### Revision IDs

The `revision` identifier inside the migration file should match the filename:

```python
# revision identifiers, used by Alembic.
revision = '003_add_skills_table'  # Must match filename (without .py)
down_revision = '002_add_session_profiles'  # Previous migration
```

### Create Date Format

Use a standardized timestamp format for documentation purposes:

```python
Create Date: 2026-01-05 13:00:00.000000
```

## Creating New Migrations

### Option 1: Manual Creation (Recommended)

1. **Determine next sequence number**:
   ```bash
   ls alembic/versions/ | tail -1
   # If last is 003_add_skills_table.py, next is 004
   ```

2. **Create file with correct name**:
   ```bash
   touch alembic/versions/004_my_new_migration.py
   ```

3. **Copy template from existing migration** and update:
   - Title/description
   - Revision ID: `'004_my_new_migration'`
   - Down revision: Previous migration ID
   - Create Date: Current timestamp
   - Upgrade/downgrade functions

### Option 2: Using Autogenerate (Requires Cleanup)

1. **Generate migration**:
   ```bash
   alembic revision --autogenerate -m "My new migration"
   ```

2. **Rename generated file**:
   ```bash
   # Alembic creates: 20260105_1430_abc123def_my_new_migration.py
   # Rename to: 004_my_new_migration.py
   mv alembic/versions/20260105_*_my_new_migration.py alembic/versions/004_my_new_migration.py
   ```

3. **Update revision ID** inside the file:
   ```python
   revision = '004_my_new_migration'  # Change from hash
   ```

4. **Update database** (if already applied):
   ```bash
   psql -h localhost -U cjei -d cjei_recommendations \
     -c "UPDATE alembic_version SET version_num = '004_my_new_migration' WHERE version_num = 'abc123def';"
   ```

## Best Practices

1. **Test migrations**: Always test both upgrade and downgrade
2. **Atomic operations**: Keep migrations focused on single logical changes
3. **Backup first**: Create database backup before applying migrations
4. **Document complex changes**: Add comments for non-obvious operations
5. **Review autogenerated code**: Alembic may not detect all changes correctly

## Common Commands

```bash
# Check current version
alembic current

# Apply all pending migrations
alembic upgrade head

# Rollback one migration
alembic downgrade -1

# Show migration history
alembic history

# Mark database at specific version (without running migrations)
alembic stamp {revision_id}
```

## Troubleshooting

### Migration Already Applied with Wrong ID

If you applied a migration with autogenerated hash ID:

```bash
# Update the database to use sequential ID
psql -U user -d database -c "UPDATE alembic_version SET version_num = '004_new_name' WHERE version_num = 'autogen_hash';"
```

### Duplicate Revision IDs

Ensure each migration has a unique revision ID. Check with:

```bash
grep -r "^revision = " alembic/versions/
```
